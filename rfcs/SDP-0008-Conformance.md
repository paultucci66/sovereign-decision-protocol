# SDP-0008: Conformance Requirements

Status: Draft Skeleton

Version: 0.1

Author: Paul Tucci

License: Apache 2.0

## Abstract

This RFC will define what it means for an implementation to conform to the Sovereign Decision Protocol.

## Purpose

The purpose of this RFC is to establish interoperability expectations for systems that create, consume, validate, store, or exchange SDP Decision Objects.

## Scope

This RFC is expected to define:

- Minimum conforming Decision Object requirements
- Producer requirements
- Consumer requirements
- Validator requirements
- Extension handling
- Version handling
- Error handling
- Required metadata
- Optional metadata
- Test vectors

## Non-Goals

This RFC will not define:

- Product certification programs
- Commercial licensing
- Specific implementation architectures
- Performance benchmarks
- Vendor-specific behavior

## Design Note

Conformance should ensure interoperability without forcing all implementations to behave identically.

The protocol should define the common contract.

Products should remain free to innovate above it.

## Open Questions

- What is the minimum conforming Decision Object?
- Should conformance levels exist?
- Should test vectors be required?
- How should extensions affect conformance?
